# overlay-focus-guard Specification

## Purpose

保证 overlay 的所有顶层浮层（组件抽屉、属性选择抽屉、编辑代码抽屉、属性编辑面板、代码编辑弹窗）在宿主页面组件库焦点陷阱激活期间，内部可聚焦控件仍能正常聚焦与输入，且对宿主页面原有焦点行为零干扰。

## Requirements

### Requirement: 浮层内聚焦不被宿主焦点陷阱抢占

当宿主页面的组件库焦点陷阱（如 antdv 的 `useLockFocus`）在 `window` 上注册了 `focusin` 全局回调并把焦点回拉到宿主容器内时，任何处于打开状态的 overlay 顶层浮层内部发生的 `focusin` 事件 SHALL 被拦截（不得继续传播到宿主注册的监听器），使浮层内的输入框、按钮等可聚焦控件保持焦点并可正常输入。

#### Scenario: 宿主抽屉打开时在组件抽屉搜索框输入

- **WHEN** 宿主页面打开了一个带焦点陷阱的抽屉（如 antdv `a-drawer`），用户进入审查模式并打开组件面板，点击「搜索组件…」输入框
- **THEN** 输入框获得并保持焦点，键入的文字正常出现在输入框内，焦点不被宿主抽屉的焦点陷阱抢回

#### Scenario: 宿主抽屉打开时在属性选择抽屉搜索框输入

- **WHEN** 宿主页面打开了一个带焦点陷阱的抽屉，用户打开属性编辑面板并从中打开属性选择抽屉，点击「搜索属性…」输入框
- **THEN** 输入框获得并保持焦点，键入的文字正常出现，焦点不被抢回

#### Scenario: 宿主抽屉打开时在编辑代码抽屉的 Monaco 编辑器输入

- **WHEN** 宿主页面打开了一个带焦点陷阱的抽屉，用户打开「编辑代码」抽屉并点击其中的 Monaco 编辑器
- **THEN** 编辑器获得并保持焦点，可正常键入代码

#### Scenario: 宿主抽屉打开时在属性编辑面板输入控件输入

- **WHEN** 宿主页面打开了一个带焦点陷阱的抽屉，用户双击元素打开属性编辑面板，点击其中的文本输入控件
- **THEN** 输入控件获得并保持焦点，键入的文字正常出现

### Requirement: 浮层外焦点行为不受影响

focus-guard 拦截 SHALL 仅作用于处于打开状态的 overlay 顶层浮层子树内部的 `focusin`；发生在浮层之外的 `focusin`（包括宿主页面自身的交互）MUST 不被拦截，宿主页面原有焦点行为保持不变。

#### Scenario: 浮层未打开时宿主正常交互

- **WHEN** 没有任何 overlay 浮层打开，用户点击宿主页面中普通抽屉内的输入框
- **THEN** 焦点行为与未安装 overlay 时完全一致，宿主焦点陷阱正常工作

#### Scenario: overlay 浮层打开期间点击宿主可审查元素

- **WHEN** overlay 浮层打开期间，用户通过审查模式与宿主页面元素交互（悬停、选中）
- **THEN** 宿主元素不因 focus-guard 获得意外的焦点行为变化
